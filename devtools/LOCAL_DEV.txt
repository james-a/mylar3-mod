Local dev — review UI / housekeeping changes
=============================================

Prerequisites: Python 3.8+ (see Mylar minimum version).

1) One-time: create a venv and install dependencies (from mylar3-src):

   python -m venv .venv
   .venv\Scripts\pip install -r requirements.txt

   (Linux/macOS: source .venv/bin/activate && pip install -r requirements.txt)

2) Create config + empty database under local-dev-data/:

   python devtools/bootstrap_local_db.py

3) Optional — one dummy series in the DB for lists/details:

   python devtools/seed_dummy_series.py

4) Start Mylar (isolated datadir; no browser; port 8090):

   python Mylar.py --datadir=local-dev-data --nolaunch -p 8090

5) Open in browser:

   http://127.0.0.1:8090/

   Log in if you set auth in config (default install may have no login).

   Housekeeping: Manage → Advanced Options → Library Housekeeping
   or http://127.0.0.1:8090/housekeeping

Using your real NAS database (optional)
---------------------------------------
Copy mylar.db (+ config.ini if you want same settings) into local-dev-data/
(backup first). Paths inside the DB still point at your NAS — some screens
expect those paths to exist; for pure UI review the dummy DB is enough.

Nothing under local-dev-data/ is committed (.gitignore).

Keeping your own config.ini safe
---------------------------------
- bootstrap_local_db.py will NOT run if local-dev-data/mylar.db already exists
  (so it will not call mylar.initialize() again and rewrite your ini).
- run_local.ps1 only runs bootstrap when mylar.db is missing.
- Mylar itself still writes config.ini when you change settings in the UI or
  when it upgrades config_version — that is normal.

Tip: keep a spare copy outside local-dev-data, e.g.
  copy local-dev-data\config.ini ..\config.ini.nas-backup
If you ever need a clean slate, delete local-dev-data\mylar.db and
local-dev-data\config.ini, then run bootstrap again.

Copied config.ini from NAS but still see "Comic Location is not set"?
--------------------------------------------------------------------
Mylar reads config from:  <datadir>\config.ini
When you use:  --datadir=local-dev-data
that file MUST be:  mylar3-src\local-dev-data\config.ini

The startup check uses [General] destination_dir (Comic Location). If that
key is missing, empty, or only whitespace, you get "not set" — even if you
thought you copied the file. Confirm the file you edited is the one under
local-dev-data (open it in an editor and search for "destination_dir").

For a Windows PC, set Comic Location to a folder that EXISTS on this
machine, for example create:

   local-dev-data\comics

and in config.ini under [General]:

   destination_dir = C:\Users\<you>\...\mylar3-src\local-dev-data\comics

(use your real absolute path). NAS paths like /volume1/... or Docker /comics
are valid on the NAS but not as a real folder on Windows unless you map a
drive to match.

If destination_dir points to a path that does not exist, the message is
different ("cannot be accessed"), not "not set".

"Could not find a valid unrar executable"
------------------------------------------
On Windows, install WinRAR (or place UnRAR.exe somewhere), OR set in
config.ini under [Metatagging]:

   unrar_cmd = C:\Program Files\WinRAR\UnRAR.exe

(adjust if your install path differs). Mylar also checks Rar.exe in
Program Files\WinRAR when unrar_cmd is blank.
